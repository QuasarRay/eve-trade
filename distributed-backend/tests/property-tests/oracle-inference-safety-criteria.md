# Practical Oracle-Inference Safety Criteria Tree

## Governing evaluation rule

```text
TEST_NAME_ORACLE_INFERENCE_IS_SAFE
=
TEST_HAS_EXACTLY_ONE_ASSIGNED_LEAF_CATEGORY
AND ALL_DOMAIN_INDEPENDENT_CRITERIA_ARE_TRUE
AND ALL_CRITERIA_FOR_THE_ASSIGNED_LEAF_CATEGORY_ARE_TRUE
```

Evaluation is deliberately single-path and deterministic:

```text
1. Route the test name to its existing single leaf category.
2. Evaluate U01 through U09 in order.
3. If one is false, STOP and record that criterion's FALSE_REASON as the single primary unsafe reason.
4. If U01-U09 are true, evaluate only the assigned leaf category's criteria in listed order.
5. If one is false, STOP and record that category-specific FALSE_REASON as the single primary unsafe reason.
6. If all applicable criteria are true, classify oracle inference as SAFE.
7. After any rewrite or decomposition, restart evaluation from U01.
```

`UNKNOWN`, `UNRESOLVED`, or `CANNOT_DETERMINE` counts as **false**.

Secondary defects may be discovered later, but they do not compete with the first false criterion for the primary disposition. This keeps later Codex instructions deterministic.

## Atomicity is not part of oracle-inference safety

A semantically explicit compound predicate can still be safe. After a name is classified SAFE, route its representation separately:

```text
SAFE_NAME_REMAINS_A_TEST
=
TEST_NAME_EXPRESSES_ONE_INDEPENDENTLY_FALSIFIABLE_OBLIGATION

SAFE_NAME_BECOMES_A_TEST_CATEGORY
=
NOT TEST_NAME_EXPRESSES_ONE_INDEPENDENTLY_FALSIFIABLE_OBLIGATION
AND COMPOSITE_OBLIGATIONS_CAN_BE_DECOMPOSED_WITHOUT_INVENTING_SEMANTICS
```
